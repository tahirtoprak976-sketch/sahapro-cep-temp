# Contract work and employee-paid material review

This release extends existing chat-approved delivery without changing schema 8 or the live relay service.

An included historical work row must explicitly declare `contract_included: true`, a selected existing site and `contract_revision` equal to that site's current `updated_at`. It cannot carry a manual price. Both preview and the final transaction require a valid open lump-sum agreement belonging to the same customer on the work date. The normal contract engine supplies `job_extra: false` and `Sözleşmeye dahil`. No contract charge or customer ledger entry is added. Existing V1 rows keep their behavior; older clients reject the new optional fields rather than importing an unpriced substitute.

`SAHAPRO_PERSONAL_EXPENSE_REVIEW_V1` only stages a local review in metadata. It references one existing historical work by ID and source row; staging binds the current local work revision for the final Save, with matching date, employee, vehicle and quarry. It supplies the confirmed net cost and VAT rate, not an assumed cash payment. The phone displays net, VAT and gross separately. Actual employee payment is initially blank and the local approval checkbox unchecked. PIN reauthentication and a local Save are required.

The normal expense model uses one gross amount both as cost and employee reimbursement. Therefore this review accepts only a confirmed actual payment equal to gross. A partial payment stays pending: no assumed vendor balance, extra reimbursement or company cash is generated. Handling partial purchases requires separately verified payable/payment evidence. Source prose and the linked work remain available for review.

Saving adds one ordinary `expense_records` record (`Personel Ödedi`, `Bekliyor`) and source/receipt metadata atomically, after backup. Existing payroll derives one reimbursement from that expense; no extra personnel event, payroll entry, cash, bank, customer ledger, fuel, stock or freight record is written. Receipt absence is explicit until an actual document is attached. Replay returns the original receipt; changed source content conflicts; deleted or edited prior expense is held for inspection.

Validation: strict plan tests cover agreement revisions, ownership, start date, status, manual-price conflict, duplicate work, payment mismatch, old-format compatibility and single payroll reimbursement. A synthetic 360px browser test covers metadata-only staging, blank/unchecked review, partial-payment hold, retained edits, actual local Save, no company money movement, replay/conflict, transaction rollback and revocation. The release workflow retains all existing checks and tests installed v3.10.38 to this version, including exact business-data preservation and offline worker assets.

The original full-gross-payment restriction described here is superseded by [optional VAT payment in v3.10.41](EXPENSE_VAT_PAYMENT140.md). The source quote is retained; the actual payment and local same-record correction are now explicit.
